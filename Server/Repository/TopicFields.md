# Поля State и Manifest топика

Справочник охватывает общую модель Repository и известные поля Archivist,
MQTT, PersistentStorage, Logram и WebUI. Это не закрытая схема всех данных
Enviriot: обычный State может быть числом, строкой, массивом или произвольным
объектом. Отсутствие пользовательского поля в справочнике не запрещает его.

Настройки и диагностические значения служебных топиков остаются в документах
модулей; отдельного указателя таких топиков здесь нет. Формат сообщений API,
записей базы и XML/XST не является форматом полей Topic.
Расширения MQTT-SN, LPLC и драйверов устройств в этот справочник не входят.

- [Расширения модулей](#расширения-manifest): архив, MQTT, Logram, Dashboard.
- [Описания типов](#описания-типов): State описания, шаблоны экземпляров и детей.
- [Схемы полей](#схемы-полей-state-и-manifest): `Fields`, `mi` и их записи.
- [Действия](#описание-действий) и [перечисления](#state-источника-перечисления).
- [Типы блоков Logram](#типы-блоков-logram): пины, служебные дети и пример NOT.
- [Проверки и поддержание](#проверки-и-поддержание-актуальности).

`Manifest.MQTT.uri` ниже означает поле `uri` вложенного объекта `MQTT`
в манифесте. В API доступа к полям это путь `MQTT.uri`.
Он не равен пути топика `/MQTT/uri`. Поля объекта State тоже не являются
дочерними топиками.

Расположение входит в определение поля: `Manifest.attr` задаёт атрибуты
топика, `Fields.<имя>.attr` — ограничения поля в редакторе, а
`Children.<имя>.manifest.attr` — атрибуты будущего дочернего топика.
Аналогично, шаблон `Children.src` не является исходником класса `State.src`.

Ни один общий валидатор не проверяет весь объект описания.
Ниже отделены рекомендуемый формат, фактическое поведение потребителя
и значения каталожных шаблонов. Значение `default` в каталоге не обязательно
совпадает с подстановкой в коде при отсутствии настройки.

## Общие поля Manifest

| Поле | Формат и назначение | Отсутствие и особенности |
|---|---|---|
| `attr` | Целочисленная битовая маска [атрибутов топика](#атрибуты-топика). | `Topic.Fill` обеспечивает числовое поле, подставляя `0`, если его не было или тип неверен. |
| `type` | Строковый путь к описанию под `/$YS/TYPES`, например `LoBlock/Binary/NOT`. | Без пригодной строки тип не разрешается. Это ссылка на описание, а не его копия; конкретный потребитель решает, какие данные читать из типа. |
| `version` | Строка вида `¤VR1.2.3`, где часть после маркера разбирается как `System.Version`. | Используется импортом XST и восстановлением PersistentStorage. Строка без маркера или с непригодной версией не участвует как корректная версия. Это не числовой счётчик и не версия всей программы. |

При импорте корректный атрибут XML `ver` записывается в `Manifest.version`.
Правила выбора версии поддерева принадлежат [XST](../Server.md#json-экранирование-и-версии)
и [восстановлению хранилища](../../plugins/PersistentStorage/PersistentStorage.md#открытие-и-восстановление),
а не шаблону создания топика.

Реализация: [Topic.Fill, SetAttribute, ClearAttribute](Topic.cs),
[TypeHelper.ResolveTypeTopic](../../plugins/WebUI/Helpers/TypeHelper.cs),
[Xst.Prepare](Xst.cs), [LiteDB_Pl.Load](../../plugins/PersistentStorage/LiteDB_Pl.cs).

### Атрибуты топика

| Имя | Значение | Смысл |
|---|---|---|
| `None` | `0` | Нет установленных битов. |
| `Required` | `1` | Запрет удаления топика средствами WebIDE; специальное создание блока также использует этот бит в шаблоне ребёнка. |
| `Readonly` | `2` | Признак недоступности редактирования State в интерфейсе. |
| `DB` | `4` | Сохранение State в PersistentStorage. |
| `Config` | `8` | Сохранение State в конфигурации XST. |
| `Saved` | `12` | Маска `DB \| Config` для проверки режима сохранения; не третий самостоятельный режим. |
| `Internal` | `64` | Служебный топик; учитывается потребителями, например исключает значения из обмена MQTT. Не универсальное правило скрытия всех представлений. |

Штатный API делает `DB` и `Config` взаимоисключающими.
PersistentStorage проверяет точное совпадение `(attr & Saved) == DB`:
ручная запись обоих битов не эквивалентна корректному режиму `DB`.
Manifest сохраняется независимо от режима сохранения State.
Последствия снятия `DB` описаны в [механизме записи](../../plugins/PersistentStorage/PersistentStorage.md#сохранение-изменений).

`Required` и `Readonly` не запрещают все вызовы серверного API из кода
и не заменяют проверку сетевого доступа. Их применение зависит от потребителя.
Не переносить смысл `DB` и `Config` на `attr` записи схемы редактора:
контекст такой записи описан [отдельно](#схемы-полей-state-и-manifest).

## Поля описания и представления

Эти поля встречаются в Manifest экземпляра и State описания типа;
некоторые также используются внутри шаблонов и схем. Одинаковый формат
не означает единого правила наследования для всех потребителей.

| Поле | Формат и смысл | Чтение и отсутствие |
|---|---|---|
| `editor` | Строковое имя редактора, например `Boolean`, `Integer`, `String`, `Enum`, `JS`. | Для топика WebUI сначала читает собственное поле, затем поле типа, затем выбирает по форме State. Пустая строка не задаёт явного редактора. Для вложенного поля используется его схема. |
| `icon` | Семантическое имя, например `Boolean`, допустимый путь к изображению или `data:image/…;base64,…`. | У топика сначала используется собственная разрешимая иконка, затем иконка типа, затем выбор по редактору/значению. У пункта меню и поля схемы иконка читается из их описания. Неизвестное имя не создаёт изображение. |
| `hint` | Строка подсказки в описании пункта меню или поля. | При отсутствии явная подсказка не задаётся. Не является вычислительным параметром и не гарантирует показ во всех представлениях. |
| `enum` | Строка с именем под `/$YS/TYPES/Enum` либо абсолютным путём к источнику перечисления. | Для редактора `Enum`: сначала собственное поле топика, затем поле типа; у вложенного поля — поле его схемы. Пустое значение не задаёт источник. Формат State источника — [ниже](#state-источника-перечисления). |
| `Children` | Объект «ключ → шаблон ребёнка» или строковый путь к каталогу шаблонов для общего Add. | Описывает возможные дочерние топики, но не создаёт их. Выбор собственного/типового каталога и запасного Core — механизм [WebUI](../../plugins/WebUI/WebUI.md#контекстное-меню-add-и-action). Logram для схемы пинов использует только объектную форму. |
| `Fields` | Объект «имя поля State → описание поля». | Схема редактирования состояния. Отсутствие не запрещает произвольное State и не создаёт значений. |
| `mi` | Объект «имя пункта/поля Manifest → описание поля». | Схема редактирования манифеста. Дополняется общим каталогом `/$YS/TYPES/Ext/Manifest`; это не Manifest самого описания. |
| `Action` | Массив или объект записей [действий](#описание-действий). | Объявляет доступные операции. Отсутствие собственного поля не отменяет объявления из типа. Не регистрирует обработчики RPC. |

`Fields` и `mi` поддерживают вложенность через одноимённый каталог внутри
описания поля. В отличие от общего `Children`, строковый путь вместо объекта
не является поддерживаемым каталогом для `SchemaOverlay`.
Состав и наложение источников описаны в [меню Inspector](../../plugins/WebUI/WebUI.md#меню-полей-inspector).

Реализация: [EditorHelper.Resolve](../../plugins/WebUI/Helpers/EditorHelper.cs),
[IconResource.Resolve, ResolveIconRef](../../plugins/WebUI/Helpers/IconResource.cs),
[EnumHelper.Resolve](../../plugins/WebUI/Helpers/EnumHelper.cs),
[SchemaOverlay.ForState, ForManifest](../../plugins/WebUI/Trees/SchemaOverlay.cs),
[MenuBuilder.ResolveAddActions, ResolveActionDescriptor](../../plugins/WebUI/Helpers/MenuBuilder.cs).

## Расширения Manifest

### Архивирование

Поля находятся в собственном Manifest архивируемого топика, не в State его типа.

| Поле | Формат и смысл | Подстановка в коде и каталог |
|---|---|---|
| `Arch.enable` | Рекомендуется Boolean: разрешение отбора изменений в архив. Чтение использует JS-приведение, поэтому `1` и непустая строка тоже включают архивирование. | Отсутствие не включает архивирование. Шаблон Add для `Arch` предлагает `true`. |
| `Arch.keep` | Число суток хранения; следует задавать конечное положительное значение. | Отсутствие, нечисловое значение, `NaN` и `<= 0` дают `10` суток. В текущем каталоге предлагается `365.25`. Положительная бесконечность отдельно не отклоняется кодом, но не является допустимой настройкой. |

Срок перечитывается при обработке пригодного изменения; включение не записывает
текущий State немедленно. Отключение не является паузой с сохранением истории.
Подробности и последствия — в [приёме изменений](../../plugins/Archivist/Archivist.md#приём-и-запись-изменений)
и [очистке](../../plugins/Archivist/Archivist.md#очистка-и-освобождение-места).

Реализация: [ArchivistPl.SubFunc](../../plugins/Archivist/ArchivistPl.cs),
[ArchStore.RefreshKeep](../../plugins/Archivist/ArchStore.cs),
[ArchRetention.IsOrphan](../../plugins/Archivist/ArchRetention.cs).
Каталожные значения: `Ext/Manifest.mi.Arch` в [base.xst](base.xst).

### MQTT

Поля находятся в собственном Manifest владельца привязки.

| Поле | Формат и смысл | Значение при отсутствии или неверном типе |
|---|---|---|
| `MQTT.uri` | Строка абсолютного URI брокера и внешней темы/фильтра, например `mqtt://broker.example/house/room/#`. | Пустая/нестроковая настройка не создаёт привязку. Непригодный URI диагностируется; шаблон каталога содержит пустую строку. |
| `MQTT.subscribe` | Boolean: приём от брокера. | `true`. |
| `MQTT.publish` | Boolean: публикация локальных значений. | `true`. |
| `MQTT.retained` | Boolean: retained у следующих исходящих публикаций. Не срок хранения локальных данных. | `false`. |

Три флага имеют строгий Boolean-тип: неверный тип, в том числе число `1`,
заменяется значением по умолчанию через `SetField`. Каталог предлагает те же
значения флагов. Применение динамическое; изменение retained не удаляет уже
сохранённое сообщение брокера. Подробности — в [настройках привязки](../../plugins/MQTT/MQTT.md#настройки-топика).

Реализация: [MQTTPl.SubFunc](../../plugins/MQTT/MQTTPl.cs),
[MqSite.ReadFlag, RefreshSettings](../../plugins/MQTT/MqSite.cs).
Правила адресов и масок не дублируются здесь: [MQTT](../../plugins/MQTT/MQTT.md#адреса-фильтры-и-значения).

### Logram

| Поле | Формат и смысл | Чтение и отсутствие |
|---|---|---|
| `Logram.block` | Маркер вычислительного блока. В каталоге обычно строка вроде `Binary/NOT`, но содержимое не выбирает класс или файл. | Проверяется определённость собственного поля, затем поля в State типа. Даже `false` считается маркером. При наличии обоих маркеров блок имеет приоритет над переменной. |
| `Logram.bind` | Строковый путь к топику-источнику. Относительный путь разрешается от самого приёмника, абсолютный — от корня Repository. | Маркер переменной может находиться в типе, но путь читается только из собственного Manifest экземпляра. `null`, нестроковое значение или неразрешённый путь не дают источника. |
| `Logram.left` | Целочисленная горизонтальная координата элемента в сетке редактора. | При чтении для отображения неверный тип даёт `0`, результат ограничивается диапазоном `0…8191`. Это не нормализация сохранённого Manifest. |
| `Logram.top` | Целочисленная вертикальная координата в той же сетке. | Те же правила чтения, что у `Logram.left`. |
| `Logram.trace` | Boolean: показ значения переменной или пина на диаграмме. | При отсутствии/неверном типе используется `false`. Это настройка представления, не журналирования скрипта. |

Для отвязки WebUI записывает `null`, а не пустую строку:
пустой путь разрешается Repository как сам топик. Несуществующий источник
не создаётся и отдельно не диагностируется. Путь — обычная строка.

Отдельные изменения координат и Trace не перепривязывают внутренние объекты.
Удаление маркера не является универсальной командой остановки уже созданного
блока. Границы изменения структуры — в [материализации](../../plugins/Logram/Logram.md#материализация-схемы)
и [подготовке связей](../../plugins/Logram/Logram.md#подготовка-связей).

Реализация: [LogramPl.Names, Claim, SubFunc](../../plugins/Logram/LogramPl.cs),
[LoVariable.ManifestChanged](../../plugins/Logram/LoVariable.cs),
[LogramGraphController.Cell](../../plugins/WebUI/Views/Logram/LogramGraphController.cs),
[LogramViewProvider.ExecuteRpc](../../plugins/WebUI/Views/Logram/LogramViewProvider.cs).
Создание класса по типу — в [описании блоков](#типы-блоков-logram).

### Dashboard

| Поле | Формат и смысл | Отсутствие |
|---|---|---|
| `dashboard.netRO` | Строковая спецификация сетей, которым разрешено чтение поддерева. | Пустое/нестроковое значение не даёт разрешения чтения от этого поля. |
| `dashboard.netRW` | Строковая спецификация сетей, которым разрешены чтение и запись. | Пустое/нестроковое значение не даёт разрешения от этого поля. |

Поддерживаются `local`, IP-адрес и CIDR, разделённые запятыми или пробелами.
Нет пригодного объявления на топике — поиск продолжается среди предков;
нет объявления вообще — нет доступа. Это особое правило ACL, не общее
наследование Manifest. Выбор наиболее конкретного объявления описан
у [WebUI](../../plugins/WebUI/WebUI.md#dashboard).

Каталог предлагает поля через пункты `DashboardRO` и `DashboardRW` с
`default: "local, 127.0.0.0/8"`. Эти имена — ключи пунктов меню;
фактический путь задаётся их `path`, а не создаётся как поле `DashboardRO`.

Реализация: [DashboardAcl.Refresh, Resolve, CanRead, CanWrite](../../plugins/WebUI/Helpers/DashboardAcl.cs),
[NetworkAcl.IsInSpec](../../plugins/WebUI/Helpers/NetworkAcl.cs).

## Описания типов

State топика описания типа — расширяемый объект `JSValue`: данные для
редактора, создателя топиков и конкретного плагина, а не исполняемая
самим Repository схема.

### Описание, шаблон и экземпляр

| Расположение | Что описывает |
|---|---|
| Manifest топика типа | Само описание: его атрибуты, редактор и тип. Например, `type: "Ext/LBDescr"` обозначает карточку для палитры Logram. |
| State топика типа | Общие метаданные, шаблоны создания и расширения модуля. |
| `State.manifest` | Шаблон Manifest будущего экземпляра. Его `type` связывает экземпляр с описанием. |
| `State.Children.<имя>` | Шаблон отдельного дочернего топика; `default` и `manifest` относятся к ребёнку, не к родителю. |
| State и Manifest экземпляра | Собственное значение и настройки уже созданного топика, не общий объект описания. |

Например, `Manifest.type: "LoBlock/Binary/NOT"` у экземпляра указывает
на `/$YS/TYPES/LoBlock/Binary/NOT`. Само описание может иметь другой
`Manifest.type` — `Ext/LBDescr`, задающий его редактирование.
Путь карточки не подставляется автоматически вместо отсутствующего
`State.manifest.type`.

Repository не объединяет Manifest экземпляра со State его типа.
Нужные унаследованные данные читает потребитель. Применение шаблона при создании
и чтение метаданных через `type` — разные механизмы:
изменение `default` или `manifest` описания не переписывает существующие
экземпляры и не означает общую горячую перезагрузку.

### Общие поля State

Шаблоном создания может быть весь State каталожного топика или запись
`Children.<имя>`. Кроме [полей представления и каталогов](#поля-описания-и-представления)
в нём используются:

| Поле | Формат и назначение | Отсутствие и особенности |
|---|---|---|
| `default` | Любое `JSValue`, начальное State создаваемого топика: в том числе объект, массив, `false` или пустая строка. | При создании топика через WebUI клонируется; отсутствие даёт `null`. Не начальные значения его детей. |
| `manifest` | Объект-шаблон Manifest создаваемого топика: `attr`, `type`, `editor` и прочие поля. | Не копия Manifest самого описания. Общий Add при отсутствии пригодного объекта передаёт пустой манифест в `Topic.Fill`. |
| `willful` | Boolean для обычного Add: запрос имени у пользователя вместо ключа шаблона. | По умолчанию `false`. Используется также при добавлении полей Inspector; специальное создание блока может игнорировать. |
| `namePrefix` | Строковый префикс автоматического имени, используемый специализированными создателями. | Обычный Add не читает. Для блока Logram отсутствие даёт `U`; каталожные блоки обычно задают `A`. Не имя класса и не путь типа. |
| `menu` | Строковый путь подменю, части разделяются `/`. | Без поля отдельное подменю не задаётся; путь папки каталога может добавляться независимо. |
| `rc` | Строка заявок на логические ресурсы внутри набора детей одного родителя: `X1` — исключительная, `S40` — совместная; несколько заявок через запятую. | Пустая/отсутствующая строка не заявляет ресурс. Не адрес устройства, не номер пина и не глобальная блокировка Repository. |

Общий Add распознаёт шаблон по определённому `default` **или** `manifest`.
Для меню добавления поля Inspector нужен `default`; оно добавляет значение
в объект, а не создаёт Topic по `manifest`.
Правила имени, ресурсов и создания остаются у
[WebUI](../../plugins/WebUI/WebUI.md#создание-топика-по-описанию).

Реализация: [MenuBuilder.IsAddAction, BuildAddItem, ResourceBusy](../../plugins/WebUI/Helpers/MenuBuilder.cs),
[TopicRpcDispatcher.ExecuteAdd](../../plugins/WebUI/Helpers/TopicRpcDispatcher.cs),

## Схемы полей State и Manifest

`Fields` описывает поля состояния, `mi` — поля манифеста.
Их ключ — имя поля или пункта добавления; значение — объект описания.
Внутренние объекты могут иметь собственный `Fields` либо `mi` для следующего
уровня. Наложение источников и выбор запасного каталога —
механизм [Inspector](../../plugins/WebUI/WebUI.md#меню-полей-inspector), не правило Repository.

| Поле записи схемы | Назначение в этом контексте |
|---|---|
| `default` | Значение, которое Add скопирует в State/Manifest. Отсутствие не создаёт пункт Add и не задаёт обязательное значение существующего поля. |
| `attr` | Числовые флаги редактора: бит `1` запрещает удаление поля, бит `2` отмечает его только для чтения. При отсутствии используется `0`. Это не атрибуты отдельного топика и не включение сохранения в DB. |
| `editor`, `icon`, `hint`, `enum` | [Метаданные](#поля-описания-и-представления) именно этого поля, а не его родителя. |
| `willful` | [Правило имени](#общие-поля-state) при добавлении поля. |
| `path` | Только для `mi`: строковый путь поля относительно текущего узла вместо ключа пункта. Например, пункт `DashboardRO` пишет `dashboard.netRO`. Пустые сегменты и `#` непригодны; при неправильном пути используется ключ. |
| `Fields`, `mi` | Каталог вложенных полей соответствующей схемы; объект, не список реальных детей Topic. |

`Fields.type` — описание пользовательского поля с именем `type`, а не новая
ссылка на тип для разрешения на каждом уровне.
Атрибуты корневого топика нельзя механически применять к корню редактора Manifest:
иначе `Readonly` состояния запрещал бы изменять манифест.

Реализация: [SchemaOverlay.ForState, ForManifest, At](../../plugins/WebUI/Trees/SchemaOverlay.cs),
[StateTreeController.BuildAddItems, BuildRow](../../plugins/WebUI/Views/InspectorState/StateTreeController.cs),
[ManifestTreeController.AddDescriptorPath, BuildRow](../../plugins/WebUI/Views/InspectorManifest/ManifestTreeController.cs),
[StateRpcDispatcher.ExecuteAdd](../../plugins/WebUI/Views/InspectorState/StateRpcDispatcher.cs),
[ManifestRpcDispatcher.ExecuteAdd](../../plugins/WebUI/Views/InspectorManifest/ManifestRpcDispatcher.cs).

## Описание действий

Записи `Action` объявляются в Manifest топика или State его типа.
Значение — массив объектов либо объект с именованными записями;
элементы, не являющиеся объектами, пропускаются.

| Поле записи | Формат и смысл |
|---|---|
| `name` | Строковое имя обработчика RPC. При отсутствии/пустой строке используется ключ записи; для массива это индекс, поэтому обычно нужно явно задавать имя. |
| `text` | Строковая подпись пункта; при отсутствии/пустой строке используется имя действия. |
| `icon`, `hint` | [Оформление](#поля-описания-и-представления) пункта, не аргументы RPC. |

Например, MQTT добавляет запись с `name: "MQTT.Reconnect"` и
`text: "Reconnect MQTT connection"`. Объявление само по себе не создаёт
обработчик: регистрация и выполнение — [механизм RPC](../../plugins/WebUI/WebUI.md#действие-и-отложенный-ответ).
Собственные записи имеют приоритет при совпадении имени с записью типа.
`willful` общего Add не является параметром вызова действия.

Реализация: [MenuBuilder.AddActionDescriptorsFromValue, AddActionItemsFromValue](../../plugins/WebUI/Helpers/MenuBuilder.cs),
[MqSite](../../plugins/MQTT/MqSite.cs).

## State источника перечисления

Поле `enum` указывает на топик, чей State — объект или массив вариантов.
Каждая строковая запись задаёт подпись; запись-объект допускает поля ниже.
У объекта значением выбора служит строковый ключ, у массива — числовой индекс.
Пользовательское поле `value` внутри записи этот выбор не переопределяет.

| Поле записи | Формат и смысл | По умолчанию |
|---|---|---|
| `text` | Строковая подпись варианта. | Ключ записи. |
| `title` | Строковая всплывающая подсказка. | Если строкового `title` нет, используется `hint`. |
| `hint` | Запасная строковая подсказка. | Без обеих подсказка не задаётся. |
| `disabled` | Boolean: вариант недоступен для выбора в редакторе. | `false`; не серверное ограничение допустимого State. |
| `order` | Число для порядка вариантов, передаваемое редактору. | При отсутствии/нечисловом значении явный порядок не передаётся. |
| `BG` | Строка цвета фона варианта. Регистр имени значим. | Пустая строка не задаёт фон. |

Отсутствующий источник или State, не являющийся объектом/массивом, не дают
списка вариантов. Иные скалярные записи преобразуются в текст;
для неопределённого значения используется ключ.
Поля `label`, `background` и `value` в ответе WebUI — результат преобразования,
а не дополнительные поля исходного описания.

Реализация: [EnumHelper.ResolveOptionsForSource, NormalizeEnumItem](../../plugins/WebUI/Helpers/EnumHelper.cs),
[редактор Enum](../../Output/www/ide/editors/enum-editor.js).

## Типы блоков Logram

### Топик описания и тип экземпляра

Каталожные описания находятся под `/$YS/TYPES/LoBlock`.
У `/$YS/TYPES/LoBlock/Binary/NOT` в [base.xst](base.xst) собственный Manifest:

```json
{"attr":69,"type":"Ext/LBDescr"}
```

`Ext/LBDescr` задаёт редактирование карточки и позволяет WebUI включить её
в палитру; это не тип будущего блока. `State.manifest.type` этой карточки
содержит `LoBlock/Binary/NOT` и копируется в Manifest экземпляра.
`State.Children.A.manifest` относится уже к ребёнку `A`.
Эти три Manifest не заменяют и не наследуют друг друга автоматически.

### Поля State блока

Блок использует [общие метаданные](#поля-описания-и-представления)
и [поля шаблона](#общие-поля-state). Их применение отличается от общего Add:

| Поля | Специфика блока |
|---|---|
| `Logram.block`, `Logram.bind` | Маркеры распознавания по [правилам Logram](#logram); `Logram.bind` не обязателен для описания блока и не задаёт унаследованный путь источника. |
| `src` | Строка с исходником JavaScript-класса. Класс создаёт экземпляр с `Calculate`; контракт и ограничения исполнения — в [Logram](../../plugins/Logram/Logram.md#поддержка-javascript). |
| `Children` | Только объект описаний детей по точным именам; строковый каталог общего Add не является схемой пинов. |
| `default`, `manifest` | Начальные данные самого блока. В каталоге State блока часто начинается с пустой строки; у некоторых типов `default` отсутствует. Значения входов/выходов задаются отдельно в `Children`. |
| `namePrefix`, `willful` | Специальное создание на диаграмме использует префикс, но игнорирует запрос имени по `willful`. Это не настройки вычислителя. |
| `icon`, `hint` | Иконка представления/палитры и подсказка карточки; исполнитель их не читает. |

Изменение исходника того же типового топика не означает автоматическую
перекомпиляцию существующих блоков. Создание экземпляров и обязательных детей
описано у [WebUI](../../plugins/WebUI/WebUI.md#создание-блока-на-диаграмме).
Чтение типа и исходника: [LoBlock.ManifestChanged](../../plugins/Logram/LoBlock.cs).

### Описание дочернего топика и пина

Запись `Children.<имя>` является [общим шаблоном](#общие-поля-state).
Ключ должен совпадать с именем реального дочернего топика.
Её `default` задаёт State ребёнка, а `manifest` — его собственные атрибуты,
редактор и другие настройки, не значения родителя.

| Поле записи | Специфика пина |
|---|---|
| `manifest.attr` | [Битовая маска топика](#атрибуты-топика). Наличие `Required` используется WebUI для создания обязательного ребёнка, даже если у него нет визуального пина. |
| `ddr` | Целое число: знак задаёт направление, модуль — строку пина на своей стороне блока. Это не слой выполнения и не приоритет вычисления. |
| `rc` | [Заявка на ресурс](#общие-поля-state), независимая от направления и строки пина. |

**Направление и положение.** `ddr < 0` — вход слева, `ddr > 0` — выход
справа. `-1` и `1` означают первые строки своих сторон, `-2` и `2` — вторые.
Индекс равен `|ddr| - 1` и ограничивается редактором значением `255`.
Пропуски номеров допустимы. Например, у Counter выход `Q` имеет `ddr: 3`,
но `rc: "X11"`: номер ресурса не определяет строку.

**Служебный ребёнок.** Отсутствующий/нулевой `ddr` означает отсутствие
визуального пина, а не дочернего топика. У Func запись `Children.src`
содержит `default: ""`, `manifest.attr: 69` и `manifest.editor: "JS"`,
но не содержит `ddr`. Это обязательный ребёнок с пользовательским текстом
функции, не исходник класса из верхнего `State.src`.

Исполнитель считает выходом собственного прямого ребёнка с положительным
`ddr`; остальные подключаемые дети и внешние топики — входные зависимости.
Редактор показывает только описанные пины с ненулевым `ddr`.
Поле `Children` само не создаёт топики: они появляются при восстановлении,
создании через WebUI или записи скрипта через `SetState`. Добавление записи
в описание не создаёт ребёнка у всех существующих экземпляров.

Реализация: [LoBlock.GetPin](../../plugins/Logram/LoBlock.cs),
[LogramGraphController.BuildLayout, TryGetDdr](../../plugins/WebUI/Views/Logram/LogramGraphController.cs),
[LogramViewProvider.CreateRequiredChildren](../../plugins/WebUI/Views/Logram/LogramViewProvider.cs).

### Пример State описания NOT

Это состав реального описания из [base.xst](base.xst).
Две длинные строки, `icon` и `src`, заменены пометками: пример иллюстрирует
структуру и не готов к импорту. Полный исходник класса остаётся в каталоге.

```json
{
  "Logram": { "block": "Binary/NOT" },
  "Children": {
    "A": {
      "default": false,
      "ddr": -1,
      "manifest": { "attr": 69 },
      "rc": "X1"
    },
    "Q": {
      "default": false,
      "ddr": 1,
      "manifest": { "attr": 65 },
      "rc": "X11"
    }
  },
  "default": "",
  "hint": "logic inverter",
  "icon": "<строка icon из каталога>",
  "manifest": { "attr": 66, "type": "LoBlock/Binary/NOT" },
  "namePrefix": "A",
  "src": "<исходник класса из каталога>",
  "willful": true
}
```

`66` у блока — `Readonly | Internal`; `69` у входа —
`Required | DB | Internal`; `65` у выхода — `Required | Internal`.
Это начальные атрибуты разных топиков, не свойства функции `Calculate`.
Режим сохранения может измениться при [подготовке связей](../../plugins/Logram/Logram.md#подготовка-связей).
